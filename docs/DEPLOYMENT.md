# النشر والنسخ الاحتياطي

## Docker Compose

استخدم التعليمات في README. في Coolify أنشئ خدمة Docker Compose من المستودع ثم انشرها؛ لا يلزم إدخال قيم أو أسرار في إعدادات الخدمة. ينشئ `init-secrets` قيمًا عشوائية للتشغيل ويحفظها في volume مستقل، ثم يبدأ PostgreSQL والتطبيق. اربط نطاق HTTPS بالخدمة على المنفذ الداخلي 8080. لا تفتح منفذ PostgreSQL للعامة؛ الشبكة الداخلية في Compose تمنع الوصول الخارجي.

## الأسرار

تُنشأ كلمة مرور PostgreSQL ومفتاح الجلسات ومفتاحا تشفير/بحث الهوية عشوائيًا عند أول تشغيل. تبقى في volume باسم `phc-runtime-secrets` ولا تُعرض على الإنترنت. احتفظ بنسخة احتياطية آمنة من هذا volume مع قاعدة البيانات؛ فقدان مفاتيح التشفير يمنع فك تشفير أرقام الهوية.

## النسخ الاحتياطي

أنشئ نسخ `pg_dump` مجدولة ومشفرة، واختبر الاستعادة إلى بيئة منفصلة. احتفظ بقاعدة البيانات ونسخة `phc-runtime-secrets` ضمن خطة الاستعادة ذات الصلاحيات المقيدة. لا تستخدم `docker compose down -v`؛ فهو يحذف البيانات والمفاتيح. لا تعتبر GitHub نسخة احتياطية لبيانات المرضى.

## النشر الأول

عند أول إقلاع تنفذ الخدمة ملفات SQL في `db/migrations` مرة واحدة. عند فتح الرابط لأول مرة، أنشئ حساب المدير من شاشة الإعداد. تُقبل عملية إنشاء واحدة فقط، وبعدها ينتقل الرابط إلى شاشة الدخول. أنشئ بقية الحسابات الشخصية بأقل دور وصلاحية عيادات مناسبة.

لا تفتح الرابط للعامة قبل إنشاء حساب المدير الأول؛ أول شخص يصل إلى شاشة الإعداد يستطيع تسجيل هذا الحساب.
