# النشر والنسخ الاحتياطي

## Docker Compose

استخدم التعليمات في README. في Coolify أنشئ خدمة Docker Compose من المستودع، وأدخل قيم `.env.example` كمتغيرات تشغيل/أسرار في إعدادات الخدمة، ثم أعد النشر. لا يلزم جعلها متغيرات بناء للصورة؛ ملف Compose يسمح بمرحلة البناء دونها، بينما يتوقف تشغيل PostgreSQL والتطبيق إذا لم تُضبط القيم المطلوبة. اربط نطاق HTTPS بالخدمة على المنفذ الداخلي 8080. لا تفتح منفذ PostgreSQL للعامة؛ الشبكة الداخلية في Compose تمنع الوصول الخارجي.

## الأسرار

أنشئ `POSTGRES_PASSWORD`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `DATA_ENCRYPTION_KEY`, و`DATA_LOOKUP_KEY` بقيم عشوائية مستقلة. خزّنها في مدير أسرار الخادم فقط. فقدان مفاتيح تشفير الهوية يمنع فك تشفير الهويات، لذلك احتفظ بنسخة احتياطية آمنة منها منفصلة عن قاعدة البيانات.

## النسخ الاحتياطي

أنشئ نسخ `pg_dump` مجدولة ومشفرة، واختبر الاستعادة إلى بيئة منفصلة. احتفظ بقاعدة البيانات ومفاتيح التشفير ضمن خطة الاستعادة ذات الصلاحيات المقيدة. لا تعتبر GitHub نسخة احتياطية لبيانات المرضى.

## النشر الأول

عند أول إقلاع تنفذ الخدمة ملفات SQL في `db/migrations` مرة واحدة، ثم تنشئ حساب مدير النظام من متغيرات البيئة إن لم يوجد. غيّر كلمة المرور الأولية من إعدادات النشر بعد تسجيل الدخول، ثم أنشئ حسابات شخصية بأقل دور وصلاحية عيادات مناسبة.
