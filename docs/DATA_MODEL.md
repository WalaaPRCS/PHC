# نموذج البيانات

## مبادئ الهوية

- المريض كيان مركزي واحد؛ `patients.patient_number` هو رقم الملف الثابت الظاهر للمستخدم.
- رقم الهوية لا يستخدم كمفتاح أساسي أو كقيمة بحث مكشوفة: يحتفظ الجدول بنص مشفر `national_id_ciphertext` وبصمة HMAC `national_id_hash` للمطابقة.
- العيادة والخدمة والزيارة والدواء والمشروع لكل منها معرّف داخلي ثابت. يحتفظ `source_record_id` في جداول المجال بمعرّف الواجهة الحالية لحين اكتمال الانتقال.
- `integration_identity_map` يحفظ علاقة `(system, entity_type, local_id, external_id, external_version)` لتفادي خلط معرّفات الأنظمة.

## العلاقات الرئيسية

| الكيان | يرتبط بـ | الغرض |
| --- | --- | --- |
| `clinics` | `clinic_services`, `staff_members`, `clinic_project_services` | تعريف المنشأة وخدماتها |
| `projects` | `project_services`, `project_indicators` | مشروع ممول وعدة خدمات ومؤشرات لكل خدمة |
| `clinic_project_services` | عيادة + خدمة مشروع + مؤشر | توزيع التغطية والهدف والنسبة على مستوى الخدمة |
| `patients` | زيارات، تطعيمات | ملف موحد عبر العيادات |
| `visits` | مريض + عيادة + خدمة | سجل سريري مرتبط بوقت ومقدم الخدمة |
| `referrals`, `lab_orders`, `immunizations` | زيارة أو مريض | نتائج/إحالات/جرعات مرتبطة بالرعاية |
| `drug_catalog` | `pharmacy_stock` | كتالوج مركزي وأرصدة منفصلة حسب العيادة والتشغيلة |
| `dispensations` | مخزون + زيارة | عملية صرف تؤثر على الرصيد وتسجل في الملف |
| `app_users`, `user_clinic_refs` | جلسات وتدقيق | دخول باسم مستخدم وكلمة مرور وتحديد النطاق |

## الانتقال من الواجهة الحالية

تستمر الواجهة مؤقتًا بإرسال مستندات JSON لكل مورد إلى `app_records`، فيما يحدث الخادم الجداول المنظمة في نفس المعاملة. لا تعد هذه الطبقة الشكل النهائي للتخزين؛ هي جسر انتقالي يقلل مخاطر إعادة كتابة جميع الشاشات دفعة واحدة. ينبغي أن تستخدم الواجهات والخدمات الجديدة الجداول المنظمة وواجهات API الموثقة.
